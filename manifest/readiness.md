# SiteForge Readiness Model

# Philosophy

Readiness is NOT:
- arbitrary field completion
- component satisfaction
- JSON population
- checklist counting

Readiness IS:
# strategic completeness.

The Factory should determine:
- whether enough strategic clarity exists
- whether enough trust exists
- whether enough conversion clarity exists
- whether enough visual direction exists

Only THEN should the system build.

---

# Previous Failure Pattern

The old system incorrectly tied readiness to:
- component requirements
- unstable JSON structures
- arbitrary fields
- inferred placeholders

This caused:
- premature builds
- forced intake behavior
- hallucinated completion
- unstable rendering
- poor strategic outputs

The new readiness system is strategy-first.

# Strategic Readiness Assembly

Once enough strategic readiness exists:
- strategy.json assembles
- site.json normalizes
- Astro rendering becomes deterministic

Readiness happens BEFORE rendering.

---

# Important Rules

## Rule 1
Components do NOT determine readiness.

---

## Rule 2
AI-generated placeholders do NOT count as readiness.

---

## Rule 3
Readiness must remain strategy-first.

---

## Rule 4
The system should ask ONLY for missing strategic clarity.

---

## Rule 5
Different archetypes require different readiness thresholds.

Example:
- visual portfolio businesses may require stronger visual readiness
- authority businesses may require stronger trust readiness
- local services may require stronger conversion readiness

The readiness model must remain adaptive.

---

# Long-Term Goal

The readiness system should eventually evolve into:
# adaptive strategic orchestration.

Meaning:
- the Factory dynamically determines what matters most
- intake adapts based on market intelligence
- build requirements evolve based on strategy
- the system behaves like a digital strategy agency
